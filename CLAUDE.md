# CLAUDE.md — правила роботи в цьому проєкті

## План

- Що за гра і які рішення ухвалено — [VISION.md](VISION.md). Порядок робіт — [ROADMAP.md](ROADMAP.md): працювати від першого невиконаного пункту, правила етапів — на початку файлу.
- Рішення, що суперечить VISION.md, — спершу узгодити з автором і оновити VISION.md.

## Симуляція балансу

- Проганяти `npm run sim` **лише тоді, коли зміна може вплинути на перемоги**: числа героя, класів, скілів, пасивок, ворогів, босів, хвиль, речей, загрози, світу (карта, маршрути), поведінка бота. Правки інтерфейсу, тексту, візуалу, документації — без симуляції.
- Останні показники для **кожного класу** (обидва набори seed) лежать у [docs/SIM_RESULTS.md](docs/SIM_RESULTS.md). Після кожного прогону онови там рядок(и), дату й причину.
- Якщо зміна стосується **одного класу** — проганяй тільки його: `npm run sim -- --class <id>` і `npm run sim -- --class <id> --seed 5000`. Режим `--class` бере рівно ті seed, які клас отримує в повному прогоні по черзі, тож результат можна ставити поруч із показниками інших класів із `docs/SIM_RESULTS.md`. Загальний відсоток рахуй із суми.
- Повний прогін усіх класів (`npm run sim` і `npm run sim -- --seed 5000`) — коли зміна зачіпає всіх (світ, вороги, боси, загроза, бот).
- Цілі (docs/archive/PLAN.md 6.11): бот зі скілами — 25–40% перемог, різниця між класами ≤ 10 п.п.; без скілів (`--no-skills`) гине на глибинах 1–3; рівень ~13 до першого боса.

## Коміти

- Коміт після кожного логічного блоку змін. Без рядків про співавторство Claude.
- Кожне оновлення, яке побачать гравці, — запис у `src/data/changelog.ts` з новою версією.
- Рішення — у [docs/DECISIONS.md](docs/DECISIONS.md), ітерації балансу — у [docs/BALANCE_LOG.md](docs/BALANCE_LOG.md).
- Усе, що не обговорено з автором і заповнено самостійно (числа, механіки, тексти, вигляд), — окремим пунктом у [docs/REVIEW.md](docs/REVIEW.md), щоб розібрати разом.
- Нові дані, які варто бачити гравцю чи розробнику (поле ворога, скіла, локації…), — показати у вікі (`src/wiki/sections.ts`, `src/wiki/story.ts`).
- Імена в текстах (репліки, квести, лор, вивіски) — **лише посиланнями** `{town:…}`, `{npc:…}`, `{boss:…}`, `{loc:…}`, `{trophy:…}`, `{name:…}` (з відмінком: `{town:capital:in}`), щоб перейменування у вікі доходило всюди. Тест `tests/content.test.ts` перевіряє, що кожне посилання існує.

## Перевірка перед комітом

`npm run typecheck && npm test && npm run build`. Візуальні зміни — знімок через CDP (головний екран гри у браузері).
